## 4. Homepage H1 Investigation (`SEO-05`)

### Root Cause
1. `src/pages/index.astro` rendered a hidden `<h1 class="sr-only">D-VIEW Solutions: Luxury Marine-Grade SS-316 Invisible Grills in Andhra Pradesh</h1>` before `<DViewWebsite client:load tier="tier1" />`.
2. Inside `src/components/DViewWebsite.tsx` (`tier === 'tier1'`), the mobile hero carousel (`lg:hidden`) rendered each of the 7 city slides with an `<h1>` heading (`<h1 className="text-[28px] font-serif ...">{slide.headline}</h1>`), while the desktop hero carousel (`hidden lg:flex`) rendered those exact same 7 slide titles as `<h2>` tags (`<h2 className="font-serif ...">{slide.headline}</h2>`).
3. Consequently:
   - Total `<h1>` tags in the homepage DOM: **8**
   - Visible `<h1>` tags on Desktop (`1440×900`): **0** (only the `sr-only` `<h1>` was active on desktop)
   - Visible `<h1>` tags on Mobile (`390×844`): **7** (all 7 mobile carousel slides were in the DOM inside the horizontal track)

### Fix Applied & Verified
1. Removed the hidden `<h1 class="sr-only">` from `src/pages/index.astro`.
2. Promoted the visible top hero slogan badge in `src/components/DViewWebsite.tsx` (`INVISIBLE GRILLS & SAFETY SOLUTIONS`) to the single semantic `<h1>` on both Mobile (`lg:hidden`) and Desktop (`hidden lg:flex`) without changing its visual typography or layout.
3. Demoted the 7 mobile carousel slide titles (`lg:hidden`) from `<h1>` to `<h2>` (and their sublines from `<h2>` to `<p>`), matching the desktop carousel slide markup.
4. **Playwright Verification:**
   - Homepage `h1DomCount`: **`1`**
   - Desktop (`1440×900`) `h1VisibleCount`: **`1`** (`— INVISIBLE GRILLS & SAFETY SOLUTIONS —`)
   - Mobile (`390×844`) `h1VisibleCount`: **`1`** (`INVISIBLE GRILLS & SAFETY SOLUTIONS`)
   - `h1SrOnlyCount`: **`0`**

## 8. Static Build vs Query-Parameter Findings (`SEO-06` & `SEO-10`)

### 8.1 Dead Build-Time `Astro.url.searchParams.get('corridor')` (`SEO-06`)
- **Root Cause:** `astro.config.mjs` configures `output: "static"`. In `src/pages/safety-pillars/[city].astro`, lines 38–52 read `const corridorParam = Astro.url.searchParams.get('corridor');` and conditionally built a corridor-specific `<title>` and `<meta name="description">`. During static site generation (`astro build`), `Astro.url.searchParams.get('corridor')` is **always `null`**, making that server-side branch dead code.
- **Fix Applied:**
  1. Simplified `src/pages/safety-pillars/[city].astro` to compute the clean, deterministic static `<title>`, `<meta name="description">`, and `<link rel="canonical" href="https://www.dviewsolutions.com/safety-pillars/${primaryCitySlug}">`.
  2. Added client-side synchronization in `src/components/DViewWebsite.tsx`: when a user navigates to `/safety-pillars/[city]?corridor=...`, React reads the `?corridor=` parameter, displays the corridor badge (`Focused on <Corridor> Corridor`), and updates `document.title` dynamically (`SS-316 Invisible Grills in ${activeCity.name} | ${corridorParam} Balcony Safety | D-View`), while keeping `<link rel="canonical">` pointed to the clean base URL (`https://www.dviewsolutions.com/safety-pillars/${primaryCitySlug}`) so query parameters never fragment indexation.
- **Playwright Verification:** Navigating to `/safety-pillars/visakhapatnam?corridor=Madhurawada+27-Floor+High-Rises` verified:
  - `document.title`: `"SS-316 Invisible Grills in Visakhapatnam | Madhurawada 27-Floor High-Rises Balcony Safety | D-View"`
  - `<link rel="canonical">`: `"https://www.dviewsolutions.com/safety-pillars/visakhapatnam"`
  - Corridor badge visible: `true`

### 8.2 Newly Discovered Alias Fallback Bug on `/safety-pillars/rajamahendravaram` and `/safety-pillars/amaravati` (`SEO-10`)
- **Root Cause:** In `src/components/DViewWebsite.tsx` (`getIndexFromSlug`), the alias map only checked `s === 'vizag'` and `s === 'vijayawada-amaravati'`, omitting `rajamahendravaram` and `amaravati`. Because `CITIES_SLIDES` uses `id: 'rajahmundry'` and `id: 'vijayawada'`, visiting `/safety-pillars/rajamahendravaram` or `/safety-pillars/amaravati` returned `-1` and silently fell back to `index 0` (**Visakhapatnam**), causing `/safety-pillars/rajamahendravaram` and `/safety-pillars/amaravati` to render Visakhapatnam's content while having `<title>` and `<link rel="canonical">` for Rajahmundry and Vijayawada!
- **Fix Applied:** Added explicit alias mappings (`if (s === 'rajamahendravaram') return 1;` and `if (s === 'amaravati' || s === 'vijayawada-amaravati') return 2;`) in `getIndexFromSlug` in `src/components/DViewWebsite.tsx`.
- **Playwright Verification:** Content similarity between `/safety-pillars/rajamahendravaram` and `/safety-pillars/rajahmundry`, and between `/safety-pillars/amaravati` and `/safety-pillars/vijayawada`, is now **`1.000` (100% identical)**.
